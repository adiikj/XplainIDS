# XplainIDS: results so far

_Generated by `make_results_md.py` on 2026-11-12 from the files in `results/`. Do not edit by hand; rerun the script after new experiments._

## 1. Summary

- **What we test:** whether an explanation-based second stage (an autoencoder on TreeSHAP vectors) helps an XGBoost intrusion detector catch attack families it never saw in training, when every system gets the same 2% false-alarm budget.

- **Main results (12 zero-day splits × 5 seeds, all at a 2% validation false-alarm budget):**
  - SHAP input beats raw input for the autoencoder: zero-day recall +0.051, 11/12 splits, p = 0.007 (Holm-corrected Wilcoxon).
  - The cascade has fewer test false alarms than XGBoost alone: test FPR -0.016, 12/12 splits, p = 0.002.
  - Zero-day recall vs XGBoost alone: +0.025, 8/12 splits, p = 0.470, not significant. It rises where XGBoost misses the held-out family and falls where XGBoost already catches it, which is what the recall-aware rule (next step) targets.

- **Status:** pipeline, cascade, alert evidence and the main grid are done. The recall-aware rule, CICIDS2017, the LLM explanation layer and the user study are next (section 10).

## 3. Training and evaluation setup

| Component | Setting |
| --- | --- |
| Preprocessing | Categorical columns ordinal-encoded on training data (unseen values → −1); stage-2 input: signed log1p (raw) or SHAP, MinMax-scaled to (−1, 1) on benign training rows |
| XGBoost | 100 trees, max depth 6, learning rate 0.3, binary logistic; trained on the full training split |
| TreeSHAP | Interventional, 500 background flows, explains P(attack); additivity checked |
| Stage-2 data | Random subsample of 50,000 training and 20,000 validation rows; detectors trained on the BENIGN rows only |
| Autoencoder | d → 64 → 16 → 64 → d, ReLU, tanh output; mean-absolute-error loss; Adam, lr 0.001, batch 512; early stopping on benign validation (patience 10, max 200 epochs); score = mean absolute reconstruction error |
| Isolation Forest | 200 trees |
| Thresholds | From benign validation flows only. Cascade: t1 (XGBoost) and t2 (stage 2) together flag exactly 2% (default 1% + 1%) |
| Zero-day protocol | Held-out family removed from training AND validation; its test flows are the zero-days. NSL-KDD official = attack types in KDDTest+ absent from KDDTrain+ |
| Statistics | Seeds 0–4; Wilcoxon signed-rank across splits (one unit per split); Holm correction |

## 9. Expected vs observed

| Expected (hypothesis)                                                                            | Observed                                                                                                                                                 |
|:-------------------------------------------------------------------------------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------|
| An AE on SHAP vectors detects zero-days better than the same AE on raw features (Barnard et al.) | Supported: zero-day recall +0.051, better on 11/12 splits, p = 0.007; AUROC on XGBoost-missed zero-days +0.058 (12/12, p = 0.003). Cost: test FPR +0.003 |
| The SHAP advantage holds for any stage-2 detector                                                | Not supported: with Isolation Forest, recall -0.006, p = 0.68                                                                                            |
| OR fusion with a separate budget per stage raises false alarms (research plan: about 2×)         | Supported: OR 2% + 2% has test FPR +0.035 higher than the cascade on 12/12 splits; its validation FPR exceeds the 2% budget                              |

| At the same budget, the cascade raises zero-day recall vs XGBoost alone                          | Not significant: +0.025, better on 8/12 splits, p = 0.47. It helps where XGBoost misses the held-out family and costs recall where it does not           |

## 10. Known issues and limitations

- **Autoencoder runs and thread count.** PyTorch's thread count changes the trained AE (NSL-KDD official seed 0: cascade zero-day recall 0.838 with 4 threads, 0.760 with the default). Part of the current grid ran before `XZ_TORCH_THREADS=4` was fixed; a rerun of the stage-2 part with 4 threads is planned, and these tables will be regenerated.
- **Validation-to-test shift.** A 2% validation budget becomes about 4–9% FPR on test (largest on UNSW-NB15, whose official train and test partitions differ), so test FPR is always reported.
- **Hard families.** NSL-KDD R2L (e.g. SNMP-based attacks that look like normal traffic) stays near 0.1–0.2 recall for every method.
- **What SHAP-based stage 2 cannot see.** A zero-day that differs only in features XGBoost never uses gets near-zero SHAP there and passes both stages.
- **Not yet done:** the recall-aware rule (E6), CICIDS2017 (E7), reproducing Barnard et al.'s large autoencoder, the faithfulness test of NOVEL evidence, the LLM layer (Feb 2027) and the user study (Apr 2027).
